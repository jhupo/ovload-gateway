## How to read this inventory

**I** means an implementation exists in this checkout. **G** means implementation is conditional on a feature switch, provider, account capability, deployment, or platform. **L** means a legacy, disabled, deprecated, or acknowledgement-only surface. None of these labels means a live integration passed testing during this audit. CRUD operations are grouped by business object; protocol aliases and internal helper functions are indexed in the appendices rather than counted as independent product features.

The catalogue and appendices together are the inventory. The catalogue explains behavior; the appendices retain every extracted API registration, frontend route, selected internal module, configuration declaration, Ent schema, and SQL migration so small operations are not lost inside a summary. A source declaration is not automatically an enabled feature.

## Important interpretation boundaries

- README/provider guides can lag the source. Grok voice and SSO conversion have implementation even where older descriptions exclude them; CN providers participate in composite routing beyond the older five-platform description.
- The opposite also occurs: data-management documentation and routes survive after the implementation was disabled. This is classified as legacy, not merely an optional external dependency.
- Async images, durable batch images, email, prompt audit and usage workers are different queues with different persistence/failure properties. Do not describe the whole application as having a single durable task queue or universal exactly-once execution.
- OpenAI Live attestation has an explicit non-Darwin unsupported implementation. Payment/media/provider configuration, account capability and feature flags must be checked before declaring a deployed endpoint usable.
- Existence of a frontend route does not guarantee the page is allowed by current auth, simple/backend mode, compliance state or feature settings. Existence of a configuration key does not prove it is currently enabled.
- Migration history includes alterations/removals and SQL-only tables; Ent schema counts are not a complete live-database table count. No database was introspected.
- The checkout contains explicit compatibility mechanisms and aliases. They are recorded as source facts, not recommendations to copy into Ovload. This report is research evidence, not an approved implementation plan.
